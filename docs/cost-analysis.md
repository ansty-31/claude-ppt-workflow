# PPT 生成成本分析（定性）

基于 SEA-Loop 中期答辩 PPT 的真实项目经验（22 页）

---

## 实际投入

**总成本：≥$50**
- 最后一天（尝试投影版改造）：约 $30
- 前期制作与探索：约 $20+

**说明**：未记录细粒度的 token 数或分阶段数据，以下为定性分析。

---

## 成本驱动因素

### 1. 学习曲线（前期探索）

**占比**：整体成本的主要部分

第一次使用 python-pptx + Claude 协作时的探索成本：
- 如何设置中文字体（`a:ea` 属性）
- 图表坐标系统、布局对齐
- 光晕效果参数调试
- LibreOffice vs PowerPoint 渲染差异

**经验**：这部分成本在后续项目可大幅复用（已有模板和工具脚本）。

---

### 2. 大文件陷阱

**案例**：让子代理读 1.3MB SVG 设计稿
- 子代理 Read 后触发 "Autocompact thrashing"
- 崩溃 2 次，每次浪费约数美元和数小时返工

**教训**：
```bash
# 正确做法（5 分钟人工）
python3 extract_coords.py design.svg > coords.txt  # 4KB
```

5 分钟人工预处理可省下数美元和数小时返工。

---

### 3. 子代理协调成本

**浪费场景**：
- 派发 3 个子代理并行改造不同页面
- 子代理花多轮"审查"已有代码而非直接改动
- 某个子代理达到 30 轮限制仍未完成任务

**根因**：
- 任务边界不明确（"先审查再决定"而非"改这 5 行"）
- 共享依赖冲突（多个代理都需要改 theme.py / charts.py）

**教训**：
- 明确单个函数的改动点，避免"审查后补齐"
- 有共享依赖时，主调度串行处理，不要并行派发

---

### 4. 需求澄清不足

**浪费案例**："投影版"尝试

用户需求："可编辑的投影版 PPTX（放大字号 + 光晕）"

**实际需要**：只是最终投影用的高质量 PDF

**错误路径**：花约 $30 尝试用 python-pptx 生成可编辑版，因各种技术问题失败

**正确路径（未采用）**：用生图模型逐页生成

**教训**：澄清"可编辑"背后的真实使用场景。

---

## 如果重来，能省多少？

假设有了现在的经验和工具：

### 优化点

1. 复用已有模板和 theme.py
2. 预提取大文件，避免崩溃
3. 明确任务边界，减少子代理轮次浪费
4. 澄清需求，投影版用生图而非可编辑 PPTX

**预计成本**：相似项目可降至数美元（而非 $50）

---

## 成本优化建议

### 1. 预处理大文件

```bash
# 让 Claude 读 1.3MB SVG ❌
# 5 分钟人工提取关键信息 ✓
python3 extract_coords.py design.svg > coords.txt
```

---

### 2. 模板化生成

```python
# ❌ 逐页调用 Claude
for page in pages:
    claude(f"生成第 {page} 页的 python-pptx 代码")

# ✓ 一次性生成模板，数据驱动
template = claude("生成 PPT 模板代码，用 {{变量}} 占位")
for data in datasets:
    exec(template.format(**data))
```

---

### 3. 明确任务边界

```bash
# ❌ 模糊任务
"先审一遍这些 G2 分支，再补齐剩下的部分"
→ 子代理花 10+ 轮反复 Read

# ✓ 明确任务
"只改 slides_hw.py 的 pool() 函数：
 - GIF 宽度改为 8.0 英寸
 - 步骤字号 22/18
 不要读其他函数"
→ 子代理 2–3 轮完成
```

## 总结

### 成本分布（定性）

1. **学习成本**：占大头，但可复用
2. **试错浪费**：大文件崩溃、需求不清、任务拆解不当
3. **有效工作**：占比较少

### 降低成本的关键

1. **减少试错**：预处理大文件，明确任务拆解
2. **复用模板**：第一次投入高，后续边际成本低
3. **选对工具**：技术内容用代码生成，视觉呈现用生图模型
4. **增量迭代**：不要一次性"完美"，先 MVP 再优化

### 最重要的教训

**成本 = 有效工作 + 试错浪费 + 返工成本**

降低总成本的关键不是"少用 AI"，而是**减少试错和返工**。

---

## 给后来者的建议

如果你要用 AI 制作 PPT：

1. **第一次预算 ×3**：试错成本远高于实际生成成本
2. **大文件必须预处理**：>200KB 的文件，先提取关键信息
3. **明确任务边界**：子代理任务 = "改这 5 行代码"，不是"审查后决定"
4. **验证逻辑分离**：语法检查每次做，视觉渲染只做一次
5. **澄清真实需求**：避免过度工程

**最后**：失败也是宝贵的数据点。这 $50 的投入换来了可复用的工具、经验文档和"什么情况下不该用 AI"的清晰认知。
